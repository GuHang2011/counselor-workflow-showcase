# 清爽校园办公 UI 与交互改版

> 历史报告中的目录是当时本地验收路径。当前公开源码已整理为 `frontend`／`backend`，路径对照见 [v1.1.1 目录说明](releases/v1.1.1.md)。

本轮按用户确认的「清爽校园办公」方向完成。修改于 2026 年 10 月 29 日开始，10 月 30 日完成验收；重点是登录、工作台、任务办理，以及全站共享的导航、表单、弹窗和表格样式。

## 逐项问题与处理

| 原有问题 | 本次处理 | 实际操作效果 |
| --- | --- | --- |
| 登录背景过重，学院识别和登录表单争抢注意力 | 使用浅青灰面板与原创 SVG 芯片、电路、学位帽插画，删去大段介绍与口号 | 学院名称明确，账号密码成为主要操作；手机首屏可直接登录 |
| 首页先展示快捷入口，待办和进度分散 | 先展示可点击的待办统计，桌面左侧待办、右侧进度与常用入口 | 辅导员先看到自己要做的事；管理员同时看到人员任务进度 |
| 不同区域字号、留白和按钮层级不一致 | 统一导航选中态、卡片边框、表头、表单、弹窗、按钮尺寸 | 日常浏览层次更清楚，桌面和手机使用同一套视觉规则 |
| 顶栏同时堆放配色切换等低频操作 | 配色快捷按钮仅在个人设置页显示；保留搜索、聊天和提醒入口 | 日常操作区域更简洁，原有三套主题仍然可用 |
| 任务页混放统计、新闻、筛选、创建等操作 | 任务范围与「安排工作任务」置顶，筛选单独一行，统计汇报放到列表之后 | 先找任务和办理，再整理成果；下载、打印、刷新增加明确文字 |
| 查看任务详情后还要关闭窗口寻找办理按钮 | 在有权限且有可用操作时，详情底部直接进入办理或审核 | 无须返回列表再找同一任务 |
| 表单误关闭会直接丢失填写内容 | 学院事务表单检测修改，关闭时提供「继续填写／放弃修改」 | 继续填写保留原内容；未修改表单直接关闭；保存或上传时禁止关闭 |
| 切换页面保留旧滚动位置，键盘用户容易迷失 | 常规页面导航回到顶部并聚焦标题，增加跳到工作内容入口 | 进入页面后从标题开始；首页定位具体记录的原有行为继续保留 |
| 空分类缺少下一步，错误统计容易误读 | 空分类提供返回全部待办；加载不完整时统计使用占位符并保留重试 | 能继续寻找待办，避免把未加载数据理解为零 |
| 手机首页上半部分过长 | 缩小统计卡片，去掉重复点击说明，将办理按钮与截止时间同排 | 降低查找首条待办的滚动成本 |
| 连续构建遗留旧资源 | 最终从全新构建目录生成候选产物 | 最终 assets 目录为 31 个文件，未混入此前迭代的脚本 |

## 部署范围

本轮未修改后端业务代码和数据库结构。新生成的候选包包含前端、现有后端 JAR、MySQL 初始化脚本、宝塔 Nginx 配置示例、服务配置、部署手册、校验值和脱敏验收摘要；不包含演示数据库、真实附件、密码或 API 密钥。已有系统升级时先备份，保留原数据库及环境配置，按包内 `DEPLOY-BAOTA.md` 操作，不要用初始化操作覆盖现有业务数据。

验收使用隔离 H2 数据库与本机 Edge，附件病毒扫描在测试环境关闭；尚未验证目标宝塔主机的 MySQL 启动、HTTPS、ClamAV 或真实外部 AI。此前报告的宝塔 MySQL 服务启动失败不属于本轮已解决事项。现有依赖漏洞告警也未因 UI 改版而消除，本包仍需目标环境上线验收。表单关闭保护覆盖当前弹窗的关闭按钮与 Escape，不等同于浏览器强制刷新后的草稿恢复。
