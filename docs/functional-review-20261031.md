# 功能设计复查与逐项修复 · v1.1.2

本轮围绕“看得懂、找得到、办得完”检查任务、提醒、审核和跟进。保留既有授权范围，优先修复妨碍日常办理的具体问题。记录日期：2026-10-31。

| 问题 | 对辅导员的影响 | 本轮解决方式 |
| --- | --- | --- |
| 点击待办弹窗或站内消息只进入列表 | 还要再次搜索任务；同一事项重复打开不生效 | 传递具体事项编号和导航次数，加载后直接打开详情或办理窗口 |
| 已提交任务的旧消息显示“事项已完成” | 把等待审核误解为已经办结 | 改为“此条提醒已结束”；实际完成状态以任务为准 |
| 手机审核缺少全选；筛选与选择范围不明确 | 重复逐项选择，容易误批筛选外事项 | 提供“全选当前待审核”，筛选改变后仅保留当前可审核选择，批量退回必须填写批注 |
| 未开始任务提前催办，新任务可设置过期截止时间 | 收到无法办理的催促，发布后立即逾期 | 服务端跳过未开始任务，前后端校验新任务截止时间必须在现在和开始时间之后 |
| 更新跟进或团党阶段可沿用过去的下次提醒时间 | 刚处理完又收到催办 | 前后端要求本次更新的下次提醒晚于现在；历史初始记录仍可登记，结束跟进仍可正常办理 |
| 页面一直使用加载时的逾期标记 | 长时间开着页面，看不到新发生的逾期 | 每分钟重新计算，已提交、已办结、已取消和未开始事项排除在逾期之外 |
| 个人统计接口失败后显示零或旧结果 | 容易误判自己没有任务或任务已完成 | 区分读取中、失败、成功，失败可重试，重新打开重新读取；说明取消任务和待审核任务口径 |

审核入口初次带“待审核”筛选进入时，自动切换到全部可见范围；这里的“全部”仍只包含服务端授权可见的任务。批量接口继续逐项检查权限、状态和版本，保留原子性，不因增加全选而放宽权限。

## 使用变化

点击提醒直接办理；需要审核时先筛选再全选，按钮数量即本次审核数量。保存进度不代表提交完成，待审核不代表已完成。跟进记录需要继续处理时选择未来日期，无需继续时结束跟进。统计出现读取失败时使用“重新读取统计”，不要把失败当成零任务。
