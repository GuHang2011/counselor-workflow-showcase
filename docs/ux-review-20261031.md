# 用户体验复查与优化 · v1.1.3

本轮于 2026-10-31 至 11-01 从辅导员日常使用顺序检查首页、工作任务、发布表单、统计与汇报。目标是减少寻找入口、解释状态和重复填写的成本。沿用已选定的“清爽校园办公”风格，重点改善常用流程与手机体验，不增加新的业务模块。

| 用户遇到的问题 | 已完成的修改 |
| --- | --- |
| 手机标题、说明和按钮占据首屏，任务出现得太靠下 | 缩短标题区，导航显示当前页面；下载和打印收进“更多”，办理按钮突出；采用独立任务卡片 |
| 从“我收到的”切到“我发布的”，已提交或已完成任务像是消失了 | 用户切换任务范围时清除旧搜索和状态筛选；“我收到的”默认待办理，“我发布的”和全部范围显示所有状态 |
| 紧急任务混在列表里，不容易判断先办什么 | 逾期优先，其次按临近截止时间排列；待审核、未开始和已办结事项分组靠后；显示是否必须提交文件 |
| 断网读取失败后看到空列表、零计数或旧记录 | 独立的失败面板和重新读取按钮，失败时隐藏误导性计数与列表，禁止导出旧结果；已有汇报编辑仍保留 |
| 发布表单的时间、文件要求和审核设置分散 | 明确填写顺序、必填标识、立即开始提示；增加 1 天后、3 天后、1 周后快捷日期；文件与验收要求集中显示 |
| 重新生成汇报或新闻直接覆盖修改，切换范围后分不清新旧汇报 | 覆盖前确认，取消保留当前内容；标记任务范围或进度变化，展示生成时间；生成和上传期间避免关闭弹窗 |
| 手机首页第一个分类始终呈深色，切换后像同时选中两个 | 仅当前分类高亮，手机分类横向滑动；保留待办、进度和常用入口的层次 |
| 正文编辑框名称不被浏览器识别，长表单难找到提交按钮 | 修正 Element Plus 旧版本的原生输入标签，增加可见正文标签；弹窗内容内部滚动，底部操作持续可见 |

## 界面变化

深蓝导航保留学院办公识别，主区域采用浅灰蓝背景、白色内容区域和轻边框。任务范围改成分段选项；表格扩大正文、状态列，缩短日期显示；手机用卡片表达接收人、标题、材料要求、进度、截止时间与下一步。逾期数量为零时不使用红色警告，待审核使用与已完成不同的颜色。输入框、悬停及按钮有轻量反馈，支持系统减少动画偏好。

没有把低频业务入口全部删除：宿舍、团党、归档等继续保持原授权入口。任务主页面专注查找与办理，报表工具保持独立区域。

## 使用提醒与边界

切换任务范围会清空搜索，避免筛选残留；如需寻找指定任务，在切换后输入关键词。手机的下载、打印在“更多”中。快捷日期按点击时刻加 24 小时、72 小时或 7 天生成，仍须符合任务开始时间的校验。汇报内容只在当前页面会话保留，刷新页面或离开模块前请先下载；本轮没有增加含学生资料的浏览器持久化草稿。

本版无数据库结构变更，未修改后端权限或生产服务器。目标宝塔 MySQL、HTTPS、附件扫描、视频处理和备份恢复仍需现场验收；旧框架和依赖风险仍在。完整部署包本地交付，GitHub 仍只发布展示、审阅源码摘录及合成数据截图。
